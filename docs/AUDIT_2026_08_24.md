# vizzz.di audit — 2026-08-24

Audited at `42f1963`. Firmware builds clean (RAM 16.1%, flash 70.5%) and the four
native tests pass. Three parallel review lanes: DMX/safety, network/HTTP, and
console UI/docs. Findings marked **[V]** were re-verified line by line against the
source (and in two cases against the Arduino core) rather than taken on the
reviewer's word.

Not a theoretical list. Every item below is reachable from a browser, a UDP
packet, or a normal night of use.

---

## Critical — fix before this touches a real rig

### 1. One oversized UDP packet permanently kills each input **[V]**

`main.cpp:621, 970, 1139, 1164` — all four pollers do
`read(buf, min(sizeof(buf), size))` and never call `flush()`.

In the Arduino core (`WiFiUdp.cpp`), `read(buf,len)` frees `rx_buffer` **only when
it is fully drained**, and `parsePacket()` opens with `if (rx_buffer) return 0;`.
So any datagram larger than the app buffer leaves a residue that is never cleared
and `parsePacket()` returns 0 forever after.

| Input | Port | Buffer | Dies on a packet of |
|---|---|---|---|
| Art-Net | 6454 | `pkt[530]` | 531 bytes |
| sACN | 5568 | `pkt[638]` | 639 bytes |
| **OSC** | 9000 | `pkt[256]` | **257 bytes** |
| Discovery | 47777 | `buf[256]` | 257 bytes |

The OSC row is the dangerous one: TouchOSC and Resolume send bundles over 256
bytes routinely, so this triggers **by accident**, not only by attack. The input
stays dead until the node is power-cycled.

Fix: `udp.flush()` after every `read()`.

### 2. Art-Net OUT feeds Art-Net IN — the rig ratchets to full and blackout stops working **[V]**

`sendArtNetOut` (`main.cpp:1109`) broadcasts the *final merged frame* on the
node's own universe. `pollArtNet` (`main.cpp:1132`) accepts any ArtDmx on that
universe with **no source-IP filter and no self-check**. Default mode is
`MERGE_HTP`, default universe is 0/0/0 on every unit, default target is the
subnet broadcast.

Two nodes, Art OUT on both: A's output becomes B's `artVals`, B outputs
`max(web_B, art_B)` and broadcasts that, A takes it back. `/blackout` and
`/net/blackout` zero only `webVals` (`:2311`, `:2775`), so the HTP maximum never
falls. The rig latches at the highest level either node ever produced and cannot
be brought down from the UI at all — only by power-cycling or turning Art OUT off.

### 3. The "Web" button permanently bricks the console **[V]**

`/web/set?en=0` (`main.cpp:2425`) persists `web_en=false` to NVS, and `setup()`
(`:2850`) then skips `setupWeb()` entirely. With no HTTP server, `/web/set?en=1`,
`/reboot` and `/factory-reset` are all unreachable, and no OSC command re-enables
it. Recovery is a serial reflash.

The button sits in the same 2×2 grid as Blackout and Full, and its confirm dialog
says only *"This will reboot the device. Continue?"*

### 4. `String` use-after-free between the web task and the DMX loop **[V]**

`/artout/peer` (`main.cpp:2559`) assigns `artOutPeerIp` on the AsyncTCP task with
**no lock**; `artOutTarget()` (`:501`) reads it from `loop()` at 43 Hz.
`String::operator=` reallocs when the new value is longer, freeing the buffer the
loop is holding. Same class of bug on `nodeName` / `apSsid` / `staSSID`, which are
written under `gLock` but read *without* it by `fillStatusJSON` in the WebSocket
push. A crash here freezes DMX with the fixtures latched at their last frame.

## High

5. **`/color/set` overwrites all 512 channels** (`:929`). One unauthenticated GET
   writes RGB triples from channel 1 across the whole universe, patch ignored —
   dimmer packs to the ceiling, movers to full pan/tilt/strobe. Also reachable
   over OSC, which forces `colorEnabled = true` with no opt-out.

6. **One global `Preferences` object used from three contexts** (`:66`).
   `Preferences::begin()` returns `false` if already started and **no call site
   checks it**. A `/scene/save` landing while the cue engine is inside
   `loadScene()` writes through the wrong handle, reports success, and the scene
   recalls later as `memset(dst,0,512)` — a full blackout mid-show.

7. **Master, ceiling and slew are applied blindly to all 512 channels** (`:1093`).
   No channel-role model exists, so pulling the master swings every mover's pan,
   tilt and colour wheel. `clampLevel` silently rewrites 246–255 to 245, which on
   a common control-channel layout turns "lamp on" into "lamp off". Burn-safe
   caps *every* channel at 96, so a mover physically cannot pan past 38%.

8. **Hold-last-on-loss is a feedback loop, not a hold** (`:1086`). With fallback
   off and master 255 the rig latches at its last level forever — there is no
   DMX-loss timeout anywhere in the file. With master at 200 the same state
   decays to black in about half a second. Which one you get depends on a setting
   the operator does not associate with either behaviour.

9. **Discovery beacon reply storm** (`:669`). `pollDiscovery` replies with a
   broadcast to *every* accepted beacon, including from peers already in the
   table, with no rate limit and no "already known" path. Two nodes sustain it
   forever; N nodes amplify it N-fold; one crafted packet ignites it. Broadcast
   frames go out at the WiFi basic rate, so it wrecks Art-Net timing for the
   whole LAN.

10. **UDP socket torn down from the web task while the loop reads it** (`:2357`).
    `/artnet/set` calls `refreshSacnSocket()` → `sacnUdp.stop()` on the AsyncTCP
    task, which `delete`s the rx buffer and closes the fd. The loop may be inside
    `parsePacket()` on that same object; the freed fd number is immediately
    reusable by lwIP, so the next `parsePacket()` can read from a TCP socket
    belonging to the web server.

11. **`delay(200)` and a SoftAP restart inside an HTTP handler** (`:2224`).
    `/wifi/scan` → `ensureStaInterface()` blocks every request and WebSocket frame
    for ≥200 ms and, in AP-only mode, restarts the access point the requesting
    browser is connected over. The UI polls this on a timer.

12. **Groups and cues are never written to flash.** Only three NVS namespaces
    exist — `cfg`, `fixtures`, `scenes`. The VJ deck offers "Save Group" and a cue
    "Save"; both are RAM-only and die on the next reboot, including the reboots
    that items 3 and 15 trigger from adjacent buttons. **[V]**

13. **Factory reset misses the fixture patch.** `loop()` (`:2881`) clears `cfg`
    and `scenes` only; the `fixtures` namespace survives. **[V]**

14. **A dropped socket kills the page rather than reconnecting** (`:1835`).
    `ws.onclose` calls `location.reload()` after 2 s — the socket drops exactly
    when the network is gone, so the reload lands on a browser error page and the
    operator loses the deck mid-show. An ESP32 reboot takes 5–10 s, far longer
    than the 2 s retry. Meanwhile every poller degrades silently: `hit()` has no
    `.catch`, so the deck keeps showing the last-known master, BPM and peer list
    as if live, and every button press is fire-and-forget with no feedback.

15. **The panic button can leave the master at full** (`:1733`). `vjPanic()`
    fires `/master?v=255` and `/blackout` as two unordered, unchecked requests.
    `routeBlackout` returns **503 and does nothing** if `gLock` is not free within
    20 ms. If the master request wins the mutex and the blackout gets the 503, the
    panic button has just set the master to full and left the levels alone. **[V]**

16. **Plain `/blackout` does nothing with a live console** (`:2311`). It zeroes
    only `webVals`, and HTP then outputs `max(webVals, netIn)`. In the default
    mode with Art-Net or sACN active, the red Blackout button changes nothing on
    stage. Only `vjPanic` forces `MODE_WEB` first.

17. **Background polling overwrites fields while you type** (`:1629`, `:1678`,
    `:1791`). A fixture name or channel number reverts every 4 s; Art-Net universe
    fields every 400 ms; BPM and depth every 2 s. Only the master guards with
    `document.activeElement`.

18. **The stage patch renders fixtures off-canvas** (`:1630`). Coordinates are
    stored 0–255 but written straight into CSS as `left:${f.x}%`. **Seen: on a
    fresh board with the firmware's own defaults, only F1 and half of F2 are
    visible — F3 and F4 are gone entirely.** `applyThunder6Mode` uses 24–88, i.e.
    the author worked around this rather than fixing it. **[V]**

19. **"THUNDER 6 Electro Mode" destroys the fixture patch with no confirmation**
    (`:1642`). Six `/fixture/set` calls overwrite fixtures 1–6 and force
    `count=6`, each one an NVS write. The button sits one row below the scene pads
    in Easy Scenes — the surface aimed at a non-programmer.

20. **A long node name freezes the whole console** (`:2517`). `routeNodeSet`
    applies the name with no length limit; the WS status buffer is 800 bytes, so a
    long name truncates every frame into invalid JSON. `ws.onmessage`'s
    `catch{return;}` swallows it and the UI freezes on the last good values
    forever — pills still reading "ART active". The same handler then walks
    `while (mdnsName.startsWith("-")) mdnsName = mdnsName.substring(1);`, so 4000
    dashes is 4000 heap realloc cycles on the web task.

## Medium

21. `masterDimmer` is not persisted (`:198`) — after any reboot the node comes
    back at master 255 while a console keeps sending full, and the rig reaches the
    ceiling within one slew ramp (~330 ms) with no operator action. Burn-safe
    survives the reboot; the master limit does not.
22. Peer table is 4 slots with no eviction (`:185`), keyed on a wire-supplied MAC
    with a spoofable source IP. Four crafted beacons lock real nodes out, and the
    `/peer/cmd` "known peer" check is then satisfied for an attacker-chosen IP —
    a constrained SSRF that will `GET /blackout|/full|/master` against any host on
    port 80. The path allowlist itself (`:403`) is sound.
23. `pMdns` is used uninitialised in `pollDiscovery` (`:626`) — a beacon with no
    `mdns` key leaks 47 bytes of stack into the peer table and out through
    `/peers`.
24. `/peers` returns truncated, unparseable JSON with four peers (`:1945`,
    `char buf[600]`, worst case ≈762). Remotely forceable via beacon names.
25. Cue timing is not `millis()`-rollover safe (`:784`) — the only absolute
    comparison in a file that otherwise uses rollover-safe deltas. At 49.7 days
    uptime the cue engine free-runs for ~300 ms, firing a scene change per loop
    iteration, each an NVS read.
26. Unbounded `fade`: `k = (elapsed << 8) / fadeTimeMs` (`:742`) overflows at
    `elapsed = 16777216 ms`. `fade=99999999` creeps for a day, then jumps
    backwards and repeats.
27. WiFi scan wedges permanently after a timeout (`:2210`) — `scanDelete()` does
    not abort the driver scan, and the recovery branch becomes unreachable. Only
    exit is a reboot.
28. `/ws` cleanup closes at most one client per 400 ms (`:2973`); a connection
    flood exhausts lwIP PCBs faster than that.
29. Burn-safe mode is persistent, halves output, and appears **nowhere** in the
    UI — no pill, no readout, no off switch. `tools/crash_http.py` turns it on by
    design, so a device left that way reads as "half-broken" with no diagnosis
    available from the browser.
30. DIR (GPIO21) floats from reset until `dmx_set_pin` (`:677`), well into
    `setup()`. `dmx_driver_install` sets RTS to receive first, so the first
    *defined* state is safe, but the window before it is undriven. One
    `pinMode(DMX_DIR, OUTPUT); digitalWrite(DMX_DIR, LOW);` at the top of `setup()`
    closes all but the bootloader time.
31. No DMX health signal anywhere (`:676`, `:1102`) — every `esp_dmx` return value
    is discarded. If the driver fails to install, the node serves its UI, reports
    `artnet_active`, and outputs nothing. `/status` has no DMX field at all, so a
    dead output is indistinguishable from a healthy one.
32. Mobile: `/vj` is **6501 CSS px — 7.1 screens of scrolling** on a 412×915
    phone, 117 buttons, **38 controls under the 44px tap-target floor**.
    `touch-action:manipulation` is set on exactly one class, so double-tap zoom is
    live on every dangerous button. `.groupTile span` (the channel range you need
    to read to know which fader you are grabbing) is ~9.3px at ~4.5:1 contrast.
    The "Off" colour swatch is grey-on-black — invisible in a dark room. **[V]**
33. **No authentication on any route**, and `/reboot` is reachable by GET
    (`:2534`) — an `<img src="http://10.0.0.1/reboot">` on any page the operator
    opens reboots the node. All JSON sets `Access-Control-Allow-Origin: *`.

## Documentation is out of date

- `CURRENT.md` baseline is `f2946cb`; HEAD is `42f1963`, **15 commits later**.
- `AGENTS.md` promises ~72 KB of flash headroom that does not exist (it states
  63.9%; the real build is 70.5%).
- `AGENTS.md` still lists fixture groups and the cue list as unbuilt backlog;
  both shipped 2026-05-07.
- The AP SSID `vizzz.di` claimed in README and AGENTS.md **can never appear** —
  `startWiFi` (`:539`) forces `vizzz.di_<MAC6>` on every boot. That same code
  rewrites a user-chosen SSID on every power cycle, and the legacy `vi_di_li`
  migration helper is never called.
- README's API table omits `/web/set`, `/reboot`, `POST /factory-reset`,
  `/fixtures`, `/fixture/set`, `/groups`, `/cue/status`, `/fx/status`. The whole
  fixture/patch feature is absent from the feature table.
- `/node/manifest` — declared the authoritative node contract — is itself missing
  `/fixtures`, `/fixture/set`, `/safety/set`, `/safety/status`, `/mode/fallback`
  and `/factory-reset`.
- Build paths in README, CURRENT.md and AGENTS.md point at `/home/nnn/...`, which
  does not exist. The working binary is `.venv-pio/bin/pio` in the project.

## Verified clean

Worth recording, so nobody re-audits it: the Art-Net and sACN parsers validate
every length field against the received byte count before each `memcpy`; the OSC
padded-string readers are bounds-clean; every HTTP-derived array index is
`constrain()`d before use, including the signed/unsigned promotions; `slewToward`,
`applyMaster` and `clampLevel` have no overflow or off-by-one; break/MAB timing
uses the library defaults, which are spec-correct. The only memory-safety defect
in the parsers is the undrained buffer in item 1.

## Suggested order

1. Item 1 — four `flush()` calls. Smallest fix, largest failure removed.
2. Items 3, 15, 16, 19 — the buttons that do something other than what they say.
3. Item 2 — a self-filter on `pollArtNet`.
4. Items 4, 6, 10 — the cross-task races.
5. Item 32 — the phone deck, before it is used at a show.
